# Virtual Redstone Wire 模组技术文档

**模组名称**：Virtual Redstone Wire（虚拟红石线缆）  
**模组ID**：`virtual-redstone-wire`  
**适用版本**：Minecraft Java Edition 1.20.1  
**模组加载器**：Forge (最新推荐: 47.x.x)  
**输出文件名**：`VirtualRedstoneWire-<版本号>-JudeBlack@qq.com.jar`  
**前置依赖**：无（纯 Forge 模组，无第三方库依赖）

## 一、参考来源与调研结果

### 1.1 参考模组：Drive-By-Wire（线缆控制）

**来源**：MC百科 (mcmod.cn) — class/18675.html  
**作者**：Endal  
**支持版本**：Forge 1.20.1

**Drive-By-Wire 模组核心机制**（调研结论）：

| 特性 | DBW 原始实现 | Virtual Redstone Wire 设计 |
|------|-------------|------------------------|
| 模组定位 | 飞行器/载具内部红石线缆布线 | 原版世界通用无线红石信号传输 |
| 线缆（Cable） | 右键创建连线 | 右键创建单向链路 |
| 线缆剪（Wire Cutter） | 右键剪除线缆 | 右键删除方块的出入链路 |
| 集线器（Controller Hub） | 方块实体，集中管理输入输出 | 无需集线器，坐标直接绑定 |
| 信号距离 | 无明确限制 | 限制 256 格 |
| 信号强度 | 无损传输 | 无损传输（同强度） |
| 多路合并 | 有 | 多输入取最大值（或逻辑） |
| 链路标识 | — | SHA-512 唯一哈希 |
| 数据存储 | — | 正向/反向邻接表 + JSON 持久化 |
| 可视化 | — | 放大镜高亮渲染 |

> Drive-By-Wire 的 Cable 物品使用流程：手持线缆右键一个方块标记起点，再右键另一个方块标记终点，创建连线。线缆剪右键方块删除连线。本模组在此基础上增加了**单向传输**、**SHA-512 唯一标识**、**放大镜可视化**和**不可见虚拟红石源方块**等特性。

## 三、核心技术要点

### 3.1 注册方式（Forge Registry 1.20.1）

使用 `DeferredRegister` 注册所有内容：

```java
public static final DeferredRegister<Item> ITEMS = 
    DeferredRegister.create(ForgeRegistries.ITEMS, MOD_ID);
public static final DeferredRegister<Block> BLOCKS = 
    DeferredRegister.create(ForgeRegistries.BLOCKS, MOD_ID);
public static final DeferredRegister<BlockEntityType<?>> BLOCK_ENTITIES = 
    DeferredRegister.create(ForgeRegistries.BLOCK_ENTITY_TYPES, MOD_ID);
```

### 3.2 物品分类

所有物品放置于原版 `CreativeModeTab.TAB_REDSTONE`（红石标签页）末尾。

在 1.20.1 中，使用 `CreativeModeTabEvent.BuildContents` 事件添加物品到已有标签页。

### 3.3 不可见虚拟红石源方块

- **方块注册**：使用 `BlockBehaviour.Properties.of().noCollission().noOcclusion().air().strength(-1, 3600000)` 属性
- **渲染类型**：`RenderType.translucent()`，全透明纹理
- **红石行为**：覆写 `getSignal` 和 `getDirectSignal` 方法，根据存储的 `Direction` 属性判断是否输出信号
- **方向存储**：通过 `BlockStateProperty<DirectionProperty>` 存储输出方向
- **信号强度存储**：通过 `BlockEntity` 或 `BlockState` 整数属性
- **防止玩家破坏**：覆写 `playerWillDestroy` 阻止破坏，或设置超高爆炸抗性

### 3.4 红石信号计算

- 在世界 Tick 或链路变更时触发
- 维护一个"脏标记"集合，记录需要重新计算的输出端
- 计算完成后更新虚拟源方块的信号强度，并调用 `Level#updateNeighborsAt` 通知邻居

### 3.5 方块高亮选中提示（客户端）

当玩家手持线缆右键方块时：
- 使用 `LevelRenderer` 的 `renderHitOutline` 自定义渲染
- 或通过 `HighlightBlockEvent` 事件修改轮廓颜色
- 输入端选中使用淡蓝色 (#0096FF) 边框

## 四、网络同步策略

### 4.1 通信协议

使用 Forge 的 `SimpleImpl` 网络系统：

| 包类型 | 方向 | 触发时机 | 内容 |
|--------|------|----------|------|
| `CableSyncPacket` | S→C | 玩家进入维度 / 重新加入 | 全量链路列表 |
| `CableUpdatePacket` | S→C | 链路增删 / 剪刀操作 | 单条链路变更（增/删） |
| `CableQueryPacket` | C→S | 放大镜右键查询 | 目标坐标 |
| `CableQueryResultPacket` | S→C | 查询响应 | 目标方块的出入链路列表 |

### 4.2 客户端缓存

- 客户端仅保存一份 `List<CableLink>` 用于渲染
- 不参与任何红石逻辑计算
- 维度切换时清除缓存

## 五、持久化方案

### 5.1 使用 Forge SavedData

每个维度独立存储，继承 `SavedData`：

```java
public class CableNetworkSavedData extends SavedData {
    // 序列化/反序列化为 JSON 字符串
    // 每维度一个文件：data/virtual-redstone-wire/cable_network_{dimension}.json
}
```

### 5.2 JSON 结构示例

```json
{
  "version": 1,
  "links": [
    {
      "id": "sha512hash...",
      "from": {"x": 100, "y": 64, "z": 200},
      "to": {"x": 105, "y": 64, "z": 205},
      "face": "NORTH"
    }
  ]
}
```

### 5.3 保存时机

- 每次链路变更后调用 `setDirty()`
- 世界卸载时自动写入
- 服务器关闭时自动写入

## 七、兼容性与注意事项

### 7.1 兼容性说明

- **原版红石元件**：虚拟源方块产生的红石信号可被所有原版红石元件（红石粉、中继器、比较器、活塞、发射器等）正常识别
- **本模组无任何第三方模组前置依赖**，链路仅绑定世界坐标，理论上可与任何模组共存
- **跨维度**：链路仅在同一维度内有效
- **区块加载**：虚拟源方块强制加载其所在区块

### 7.2 性能考量

- 邻接表使用 `HashMap<BlockPos, HashSet<Target>>` 结构，平均 O(1) 查找
- 渲染时距离裁剪，超过配置距离不渲染
- 红石计算采用脏标记机制，避免每 tick 全量扫描
- 单维度链路数量建议不超过 10000 条

### 7.3 安全边界

- 输入坐标可为任意位置（虚空、封闭空间均可）
- 输出端若在未加载区块，强制加载区块并放置虚拟源方块
- 服务器管理员可通过指令清空指定维度的所有链路数据
