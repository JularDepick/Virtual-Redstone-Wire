# Fabric 侧实测清单

本清单用于验证 Fabric 侧实现与 Forge 基线**功能等价**

通用功能在 Forge 侧已被反复验证,两侧源码同名同构,因此本清单的重点放在**两侧存在差异的地方**:差异处才是移植真正引入的风险,逐项判定标准写清楚,便于逐条打勾

## 一,配置界面入口

Forge 侧把配置界面注册进 Mods 菜单, Fabric 侧没有对应机制, 改用客户端命令 `/vredconfig` 作为入口,这是两侧的有意分歧之一, 验证项如下

| 项 | 判定标准 | 为什么查它 |
|:---:|:---|:---|
| 命令可用 | 输入 `/vredconfig` 能打开配置索引页 | 入口是自建命令, 不是加载器菜单 |
| Tab 补全 | 输入前缀能被补全出该命令 | 命令的可发现性, 也是选它而非快捷键的理由 |
| 改值落盘 | 在界面改值后写回配置文件, 重启后仍是新值 | 界面与自建配置设施的配合 |
| 关闭返回 | 关闭界面后回到游戏, 不残留暂停或黑屏 | 该界面以无父级方式打开 |

## 二,平台差异专项

### 2.1 邻居方块更新钩子

Fabric 侧没有邻居更新事件,改由 Mixin 在 `Level.updateNeighborsAtExceptFromFacing` 尾部注入

| 项 | 判定标准 | 为什么查它 |
|:---:|:---|:---|
| 拉杆变化 | 拨动拉杆,已建链的输出方块上的红石灯立即亮灭 | 该钩子是信号源变化的唯一入口,失效则表现为"灯永远不亮" |
| 红石块放置 | 在输入方块旁放置或破坏红石块,输出端立即响应 | 同上,且属"信号源以邻居身份到达"的路径 |
| 红石线接入 | 红石线信号变化传导到输入方块时输出端跟随 | 验证被通知邻居集合是否完整 |
| 与基线一致 | 同一装置在 Forge 侧与 Fabric 侧表现相同 | 逐项对照,避免"两侧都错但错法不同" |

### 2.2 弱充能判据的还原

Forge 侧 `Level.getSignal` 会在方块需要检查弱充能时把直连信号计入最大值,其判据是加载器钩子 `shouldCheckWeakPower`,原版没有;Fabric 侧按其默认实现所用的原版判据 `isRedstoneConductor` 还原

| 项 | 判定标准 | 为什么查它 |
|:---:|:---|:---|
| 强充能方块 | 石头等不透明方块被充能时,其相邻的红石线是否被点亮 | 该判据决定强充能是否参与取值,是本移植唯一的语义重建 |
| 非导体 | 玻璃等非导体不参与该判定,行为应与 Forge 侧一致 | 判据若还原错误,这里会先暴露 |
| 比较器与活塞 | 行为回到原版,不因本模组而变化 | 与故意设计一致:仅覆写 getSignal,不覆写 getDirectSignal |

### 2.3 自建配置

Fabric 侧没有加载器代管的配置系统,由模组自行读写文件

| 项 | 判定标准 | 为什么查它 |
|:---:|:---|:---|
| 首次生成 | 首次启动后配置文件出现在配置目录,字段名与默认值与 Forge 侧一致 | 自建读写路径的入口 |
| 取值范围 | 越界值被忽略,不写入也不生效 | 整数条目的范围约束在读写两侧都要生效 |
| 枚举项 | 日志分割模式的三个取值可正确读写 | 枚举的序列化形式与 Forge 侧一致 |
| 改值后落盘 | 通过界面或命令改值后写回文件,重启后仍是新值 | 自建实现里"改内存值"与"写文件"是两件事 |
| 服务端改值广播 | 服务端改值后在线客户端立即采用新值 | 原实现依赖加载器的配置同步,Fabric 侧靠网络包 |
| 服务端配置页权限 | 非存档拥有者看不到也改不了服务端配置 | 走网络包校验,与 Forge 侧同一口径 |

### 2.4 协议版本握手

Forge 侧由通道在连接阶段校验协议版本,Fabric 侧改为加入后由客户端比对并自行断开

| 项 | 判定标准 | 为什么查它 |
|:---:|:---|:---|
| 版本一致 | 正常加入,无提示,功能可用 | 握手不得误伤正常连接 |
| 版本不一致 | 客户端收到提示并断开,且不出现按错误格式解析的异常 | 这是补上该机制的唯一目的 |
| 提示文案 | 提示显示两端版本号,中英文均正确 | 缺翻译会显示原始键名 |

### 2.5 按键与修饰键

| 项 | 判定标准 | 为什么查它 |
|:---:|:---|:---|
| 按住 Ctrl 生效 | 按住 Ctrl 再按 Z 与 Y,撤销与重做生效 | 原版按键无修饰键概念,判定在代码里 |
| 不按 Ctrl 不生效 | 单按 Z 与 Y 不触发任何动作,且不产生积压 | 防止"未按 Ctrl 时的点击在按键对象内积压" |
| 历史窗口页 | 手持放大镜时按住 Ctrl 再按 A 打开历史窗口页 | 同一判定路径的第三个按键 |
| 控制菜单显示 | 三个绑定的显示文案含"按住 Ctrl"提示 | 原版不显示修饰键,文案是唯一的告知途径 |

### 2.6 渲染挂载

| 项 | 判定标准 | 为什么查它 |
|:---:|:---|:---|
| 三要素齐全 | 手持对应物品时看到起点框,终点框与链路红线 | 渲染入口换成了另一个回调 |
| 遮挡关系 | 玻璃,水,玻璃板,不透明墙的遮挡表现与 Forge 侧一致 | 深度行为取决于所用渲染类型,换挂载点可能改变绘制时机 |
| 透明度链 | Fabulous 与非 Fabulous 两条路径都覆盖 | 与 Forge 侧同一要求 |
| 渲染距离 | 超出放大镜渲染距离的链路不渲染 | 判定逻辑未改,但需确认新入口下仍生效 |
| 维度守卫 | 换维度瞬间不把旧维度链路画到当前维度 | 缓存维度校验与渲染入口的配合 |

### 2.7 HUD

| 项 | 判定标准 | 为什么查它 |
|:---:|:---|:---|
| 位置 | 提示紧贴快捷栏上方,不与物品名称框重叠 | 几何常量未改,但换成了另一个回调,绘制顺序可能不同 |
| 时长 | 显示 2 秒后消失 | 计时逻辑未改 |
| 历史窗口页打开时不渲染 | 窗口页打开期间不出现该提示 | 避免遮挡窗口页 |

### 2.8 存档写回

Forge 侧在逐维度保存事件里写回,Fabric 侧改为逐 tick 让存档载体指向实时网络并置脏

| 项 | 判定标准 | 为什么查它 |
|:---:|:---|:---|
| 退出重进 | 建链后退出游戏并重进,链路仍在 | 落盘时机换了,这是最直接的验证 |
| 崩溃后 | 异常退出后重进,最近一次变更是否还在 | 逐 tick 置脏的语义是"始终可落盘" |
| 换维度 | 各维度数据互不串写 | 按维度分别写回 |

## 三,平台级启动检查

| 项 | 判定标准 | 为什么查它 |
|:---:|:---|:---|
| 专用服务端启动 | 服务端能加载模组并进入世界, 日志中无 NoClassDefFoundError 与缺失客户端类的报错 | 公共包里有 10 个文件引用了客户端专属 API, 服务端安全靠 JVM 惰性解析与客户端入口隔离来保证, 这是该推理的确定性验证 |
| 客户端启动 | 客户端能加载模组并进入世界, 三个物品可用 | 客户端入口的各项注册是否齐全 |
| 模组元信息 | 游戏不因版本谓词或元信息问题拒绝加载模组 | 谓词已用加载器解析器验过, 这里是端到端确认 |

## 四,通用项

以下功能两侧源码一致,各跑一轮确认无平台相关回归即可:

| 项 | 判定标准 |
|:---:|:---|
| 建链与删链 | 右键选中输入与输出端建链,线缆剪批量删除 |
| 一对多与多对一 | 广播与合并取最大值 |
| 撤销与重做 | 双栈历史与提示 |
| 放大镜查询 | 面板与飘浮两种查询 |
| 网络往返 | 各报文类型的收发均正常 |
| 创造模式标签页 | 三个物品出现在红石标签页 |
