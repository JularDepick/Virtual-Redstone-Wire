# 多版本兼容实测清单

本清单把"四个目标各实测一次"落成可逐项打勾的检查项, 重点放在**各目标自己改动过的补丁层**上: 通用功能在基线上已被反复验证, 真正会因版本差异出问题的是那些被补丁层改过的地方

## 1. 使用方式

- 每个目标至少在一台客户端与一个专用服务端上各跑一轮, 两侧必须使用**同一份**产物
- 服务端可开启内置自动化诊断: 启动参数加 `-Dvred.test=true`, 载入主世界时会自动跑一遍诊断并输出到日志, 先看这一项再人工测
- 顺序建议: 服务端日志无异常 -> 客户端进世界 -> 再按第 3 节逐项确认
- 每项填 通过 / 失败 / 未测; 失败项附日志片段

## 2. 通用项(四个目标都要过)

| 项 | 判定标准 |
|:---:|:---:|
| 模组加载 | 日志出现主类初始化行, 无类加载或方法缺失错误 |
| 服务端配置生成 | 世界目录出现服务端配置 toml |
| 客户端配置生成 | 配置目录出现客户端配置 toml |
| 链路增删同步 | 一端建链或删链, 另一端在数 tick 内看到高亮变化 |
| 存档往返 | 建链后退出并重进, 链路仍在 |
| 物品悬浮提示 | 三个物品的提示行正常显示 |
| 配置界面 | Mods 菜单能打开配置索引页与两个子页 |
| 红线与边框 | 手持对应物品时看到起点框, 终点框与链路红线 |

## 3. 各目标专项

### 3.1 mc-1.20_1.20.1-forge

该目标相对基线的差异只有主类一份, 内容取自共用层 `container-fallback`(改主类取容器的方式), 逐条见该目标目录的 `diff-baseline.json`

| 项 | 判定标准 | 为什么查它 |
|:---:|:---:|:---:|
| 配置注册 | 服务端 toml 生成且客户端配置页可打开, 可改值 | 取容器方式若失效, 表现就是配置不生成或配置界面报错 |
| 覆盖两端 | 在 1.20 与 1.20.1 各跑一轮 | 该产物覆盖两条 MC 版本线 |

### 3.2 mc-1.20.2-forge

该目标的内容来自共用层 `container-fallback` + `forge-48`(网络通道整体重写) + `vanilla-48`(三个配置页背景签名, 两个页面滚轮签名), 逐条见该目标目录的 `diff-baseline.json`

| 项 | 判定标准 | 为什么查它 |
|:---:|:---:|:---:|
| 六个包的收发 | 建链删链广播, 放大镜信号查询的请求与响应, 服务端配置的请求与响应全部正常 | 网络通道按 48.x 新入口重写, 是全项目改动面最大处 |
| 定向投递 | 单玩家, 整维度, 全体三种投递都到达 | 投递参数顺序与上行入口被改过 |
| 配置页背景 | 三个配置页背景为黑色半透明, 不出现原版模糊或泥土背景 | 背景覆写点签名被改过 |
| 列表滚轮 | 配置列表可用滚轮滚动且不越界 | 滚轮签名新增了形参 |

### 3.3 mc-1.20.3_1.20.4-forge

该目标复用 3.2 的网络与配置界面内容, 区别在三个配置界面取自共用层 `vanilla-1203`, 即 1.20.3 起的列表构造器与坐标访问方式, 逐条见该目标目录的 `diff-baseline.json`

| 项 | 判定标准 | 为什么查它 |
|:---:|:---:|:---:|
| 六个包的收发 | 同 3.2 | 与 3.2 共用同一套网络内容 |
| 配置页背景与列表滚轮 | 同 3.2 | 与 3.2 共用同一套配置界面内容 |
| 列表构造器 | 三个配置页的条目可正常滚动与点击, 不出现错位 | 该内容采用 1.20.3 起的列表构造器与坐标访问方式, 与 1.20.2 的形态不同 |
| 覆盖两端 | 在 1.20.3 与 1.20.4 各跑一轮 | 该产物覆盖两条 MC 版本线 |

### 3.4 mc-1.20.6-forge

该目标的内容最多: `forge-48` + `vanilla-48` + `vanilla-1203` + `vanilla-1205` + `forge-50`, 逐条见该目标目录的 `diff-baseline.json`

| 项 | 判定标准 | 为什么查它 |
|:---:|:---:|:---:|
| 存档往返 | 退出重进后链路仍在, 日志无存档写入异常 | 存档读写签名在 1.20.5 起增加了一个形参 |
| 物品悬浮提示 | 三个物品的提示行正常显示 | 提示方法的第二形参类型在 1.20.5 起改变 |
| 线缆高亮位置 | 起终点边框与红线**与方块严格重合**, 无整体偏移 | 渲染事件给出的姿态由对象改为矩阵 |
| 逐 tick 功能 | 撤销与重做快捷键, 三物品"长按不重复", 换维度后缓存复位均正常 | 事件的相位判断改为订阅按相位分的子类 |
| 同 tick 冲突 | 同 tick 内相同请求合并, 相背请求拒绝, 不同目标各自独立 | 服务端 tick 队列由上述相位订阅驱动 |
| 配置列表几何 | 列表不覆盖到底部按钮, 滚动条紧贴右缘 | 列表构造器不再接收底部坐标, 滚动条位置访问器改名 |
| 配置界面与滚轮 | 三个配置页背景与滚轮正常 | 同 3.2 的两项 |
| 放大镜飘浮提示 | 出现在快捷栏上方紧贴位置, 约 2 秒后消失, 内嵌颜色正常, 打开撤销历史窗口页时不渲染 | 该目标是唯一使用 HUD 注入挂载点的, 也是本轮新增的挂载方式 |
| 运行环境 | 客户端使用 Java 21 | 该版本 Forge 要求 Java 21 |

## 4. 记录与归档

- 服务端自动化诊断结果与人工实测结论一并记入评估报告的实测章节
- 失败项必须记录: 目标标识, MC 与 Forge 版本, 复现步骤, 日志片段, 是否可稳定复现

## 5. 本清单不覆盖的部分

- 面板内的主观观感(表格列宽, 换行位置, 悬浮提示时序)由人工判定, 本清单只给判定标准不给阈值
- 多人并发下的同 tick 冲突边界, 以及大规模链路下的分片行为, 需要专门构造场景, 不属本清单的常规项
